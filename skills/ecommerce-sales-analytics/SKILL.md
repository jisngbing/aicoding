# 电商销售统计与展示

先判断用户需要“分析已有销售数据”，还是“开发销售统计功能”。围绕销售统计推进，不因使用本技能自动创建仓库、提交代码、推送或发布系统。

## 数据与口径

1. 分析数据时定位用户指定的 CSV、Excel、数据库或 API；开发功能时先读取现有订单、支付、退款的数据模型和前端组件。没有真实数据就说明缺少什么；只在用户需要演示时生成清楚标为“演示数据”的样例。
2. 按需读取 [references/metrics.md](references/metrics.md)，明确日期范围、业务时区、币种、订单状态、金额是否含优惠/运费/税、退款归属。能从项目确定的口径直接沿用并说明，无法确定且影响结论的再询问。
3. 检查数据粒度：订单级金额不能在订单商品行上重复求和；订单数按 order_id 去重，商品销量按商品行数量汇总。不要通过买家姓名去重或把销售额叫作利润。
4. 金额计算使用 Decimal 或数据库定点数。多币种分开显示；没有汇率和换算日期时不合计。用支付日期统计实收销售，以退款发生日期统计现金退款，或以订单归属统计销售队列退款，两者必须标明。

## 分析已有销售数据

在 aicoding 中，用户可从前端“CSV统计”上传CSV并获得 file_id。优先调用已注册的 `analyze_sales_csv` 工具，复用上传时识别的字段映射；成功后将返回的 `artifacts.dashboard` 作为看板链接，附汇总CSV下载链接。无需克隆仓库或执行脚本。缺少状态/退款字段时，仅在用户确认后设置 assume_paid/assume_no_refunds；不能自行填零。该工具支持中英文表头、UTF-8/GB18030、日期与粒度选择。只有其他环境未提供该工具时，再使用下述独立脚本。

优先使用数据所在环境已有的聚合工具；CSV 可使用本技能的 [scripts/sales_report.py](scripts/sales_report.py)。此脚本只读输入，生成离线 HTML 图表和 JSON，不安装依赖、不调用外部服务。

- 输入约定及样例见 [assets/sales-template.csv](assets/sales-template.csv)。先把真实字段映射为样例列，不能仅改列名就假设订单总额等于商品行实收。
- 每行是一个唯一订单商品行，paid_amount/refund_amount 都是该行金额；脚本将退款归属到原支付日，不能用于退款发生日现金流分析。
- 支持 paid、completed、partially_refunded、refunded；排除 unpaid、cancelled，其他状态报错，先完成显式映射。当前状态不能用于重建历史时点状态。
- 输入 paid_date 必须为已转换到业务时区的 YYYY-MM-DD，不将 UTC 日期直接截断当本地日期。脚本不负责兑换汇率。
- 执行环境路径与文件工具虚拟路径不同。先通过 execute 确定脚本、数据文件在当前沙箱的实际位置；必要时把脚本复制到允许执行的项目目录。不要把 /skills 虚拟路径或开发者机器绝对路径直接作为所有沙箱的执行命令。

命令模板（将占位符替换为当前执行环境真实路径）：

```text
python <script-path>/sales_report.py <sales.csv> --output <report-directory> --start 2026-10-01 --end 2026-10-31 --currency CNY
```

默认交付：实收销售额、退款额、净销售额、支付订单数、购买人数、客单价、商品销量；按日销售趋势、净销售额 Top10 商品、商品明细表。附数据时间范围、排除行数、指标定义和至少一项可由结果支持的观察。不能把描述相关性的趋势说成因果。

## 在现有项目实现统计页面

根据仓库现有架构落地，不强行换框架或新建独立站点。前后端使用一致的筛选条件与指标定义。

- 后端：按权限限定店铺/租户，接受起止日期、店铺、商品/品类等现有维度；数据库完成聚合，分页返回明细；支付表和退款表先分别按订单或商品行聚合再关联，避免一对多 JOIN 放大金额。不对数据执行修改。
- 前端：顶部日期筛选与口径提示，其后指标卡、销售趋势、商品 Top10、明细表。沿用现有 UI 组件与图表库；没有图表库时静态报表可以使用 SVG。金额显示币种和单位，图表说明实收还是净额。
- 交互：提供加载、无数据、失败重试状态；修改日期同步刷新全部区块。支持移动端和表格横向滚动。不用随机数填充真实业务页面，也不把买家个人信息嵌入看板。
- 比较：用户需要环比/同比且数据充足时再提供；上一期为0时显示“无可比基数”，不显示无穷大。缺访客/成本/广告数据时，不生成转化率、毛利或 ROI。

## 验证与交付

用包含多商品订单、部分退款、取消订单、重复行及零销售的样本核对：订单去重、净额=实收−退款、各商品和各日期合计与总额一致；无分母时比率显示不可计算。实际运行生成脚本或项目相关检查，说明通过情况。

交付报告/页面入口、数据范围、统计口径和已验证的结果。若只生成离线报告，不宣称已经上线页面或接入实时数据库。
